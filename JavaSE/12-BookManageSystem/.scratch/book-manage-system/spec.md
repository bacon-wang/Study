# 规格：图书管理系统

Status: ready-for-human

## Problem Statement

一个小图书馆用纸笔管理馆藏和借还：不知道哪本书在借、借给了谁，读者一次借了多少本没人限制，下架的书和它的借阅历史对不上，也说不清哪些书长期没人借、该清理了。管理员和读者需要一个简单的工具，在一台电脑上完成这些事，关掉程序再打开时数据还在。

## Solution

一个 Java 控制台程序。用户输入自己的 ID 登录，只看到自己角色能用的菜单：

- **管理员**：上架、修改、下架图书，查看累计借阅次数、热门图书、库存状态，批量清理旧书。
- **读者**：借阅、归还图书，查看自己的在借和历史借阅记录。
- **两种角色都能**：查找图书、浏览馆藏。

每次修改都马上保存到本地文本文件，写到一半崩溃也不会损坏原有数据。任何输入错误都只会提示后重新输入，不会让程序退出。

## User Stories

### 登录与会话

1. 作为用户，我想输入自己的用户 ID 登录，这样系统知道我是谁、是什么角色。
2. 作为用户，我想在输错用户 ID 时看到提示并重新输入，这样输错一次不会退出程序。
3. 作为用户，我想在输入非数字的用户 ID 时被提示重输，这样误按键不会让程序崩溃。
4. 作为管理员，我想登录后只看到管理员可用的菜单项，这样不会被无关功能干扰。
5. 作为读者，我想登录后只看到读者可用的菜单项，这样不会误以为自己能上架、下架。
6. 作为用户，我想选择注销回到登录界面，这样另一个人可以在同一台电脑上登录。
7. 作为用户，我想在登录界面选择退出程序，这样用完可以正常关闭。
8. 作为用户，我想在菜单里输入不存在的编号或非数字时被提示重输，这样不会误触发操作或崩溃。
9. 作为维护者，我想直接编辑用户文件来增删用户，这样不需要在程序里做用户管理。
10. 作为维护者，我想在用户文件缺失或没有任何用户时，启动就看到明确的报错，提示先添加管理员，这样不会进入一个谁都登录不了的程序。

### 查找与浏览

11. 作为用户，我想浏览全部在馆图书，并看到每本是否在借，这样知道馆里有哪些书、哪些现在可借。
12. 作为用户，我想按书名的一部分模糊查找图书，这样记不全书名也能找到。
13. 作为用户，我想按作者的一部分模糊查找图书，这样能找到某位作者的所有书。
14. 作为用户，我想按类别的一部分模糊查找图书，这样能浏览某一类书。
15. 作为用户，我想按图书 ID 精确查找，这样能确认某本书的详细信息。
16. 作为用户，我想在查找不到结果时看到明确提示，这样知道是真的没有，而不是程序出错。
17. 作为用户，我想查找和浏览的结果里不出现已下架的图书，这样不会去借一本已经不在馆藏里的书。
18. 作为用户，我想按 ID 查找一本已下架的图书时被告知"图书不存在或已下架"，这样不会误以为它还在馆。

### 维护馆藏

19. 作为管理员，我想录入书名、作者、类别、出版年份来上架一本新书，这样它就进入馆藏。
20. 作为管理员，我想上架时由系统自动分配图书 ID 和上架日期，这样不用自己编号，也不会和已有图书冲突。
21. 作为管理员，我想新图书的 ID 永远不和任何已有或已下架图书重复，这样借阅历史始终指向正确的书。
22. 作为管理员，我想在书名、作者或类别为空（或只有空格）时被提示重输，这样馆藏里不会出现无名书。
23. 作为管理员，我想输入的书名、作者、类别自动去掉首尾空格，这样查找时不会因为多一个空格匹配不上。
24. 作为管理员，我想在出版年份不是整数，或不在 1 到今年之间时被提示重输，这样不会录入荒谬的年份。
25. 作为管理员，我想书名里含逗号、Tab、换行、反斜杠时也能正确保存，重启后原样显示，这样任何书名都不会把数据弄乱。
26. 作为管理员，我想按 ID 修改一本在馆图书的书名、作者、类别、出版年份，这样能更正录入错误。
27. 作为管理员，我想修改时对某个字段直接回车表示保留原值，这样只改一个字段时不用重新输入全部字段。
28. 作为管理员，我想修改时同样受上架时的字段校验约束，这样修改也不会引入非法数据。
29. 作为管理员，我想修改一本已下架的图书时被告知"图书不存在或已下架"，这样不会白改一本已经不在馆藏里的书。
30. 作为管理员，我想按 ID 下架一本在馆图书，这样它不再出现在浏览和借阅中。
31. 作为管理员，我想下架一本在借的图书时被拒绝并看到原因，这样不会出现读者手里拿着一本已下架的书。
32. 作为管理员，我想下架后图书的借阅历史仍然保留，这样统计和读者历史不会丢失。
33. 作为管理员，我想下架不可恢复，这样图书的状态只会从在馆变为已下架，规则简单。

### 借阅与归还

34. 作为读者，我想按图书 ID 借阅一本可借的图书，这样能把书带走。
35. 作为读者，我想借阅成功时看到借阅日期，这样知道是哪天借的。
36. 作为读者，我想借一本在借的图书时被拒绝并看到原因，这样知道它已经被别人借走。
37. 作为读者，我想借一本不存在或已下架的图书时被告知"图书不存在或已下架"，这样知道输错了 ID 或书已不在馆。
38. 作为读者，我想在已有 5 本在借时再借被拒绝并看到借阅上限，这样知道要先还书。
39. 作为维护者，我想借阅上限可以在配置里调整，这样以后改规则不用改业务代码。
40. 作为读者，我想按图书 ID 归还一本自己在借的图书，这样它重新变为可借。
41. 作为读者，我想归还时由系统记录归还日期，这样历史里能看到这次借了多久。
42. 作为读者，我想归还一本别人借的或没有在借的图书时被拒绝并看到原因，这样不会误还别人的书。
43. 作为读者，我想查看"我的借阅"，分成当前在借和历史记录两部分，并显示借出和归还日期，这样清楚自己借过什么、还有什么没还。
44. 作为读者，我想在"我的借阅"历史里看到已下架图书的记录并标注"已下架"，这样历史是完整的。

### 统计与库存

45. 作为管理员，我想查看每本图书的累计借阅次数，这样知道哪些书受欢迎。
46. 作为管理员，我想累计借阅次数只在借出时增加、归还时不减少，这样它反映的是被借过多少次。
47. 作为管理员，我想统计里也包含已下架的图书，并标注"已下架"，这样历史数据不丢。
48. 作为管理员，我想输入 K 查看累计借阅次数最多的前 K 本在馆图书，这样决定采购或推荐。
49. 作为管理员，我想 K 大于在馆图书数时直接看到全部在馆图书，这样不会报错。
50. 作为管理员，我想次数相同的图书按 ID 升序排列，这样每次结果都一样。
51. 作为管理员，我想在 K 不是正整数时被提示重输，这样不会得到无意义的结果。
52. 作为管理员，我想查看库存状态：每本在馆图书是否在借、借给了哪位读者，这样能追到书在谁手里。

### 旧书清理

53. 作为管理员，我想列出所有旧书，也就是上架满旧书阈值、且最近旧书阈值天数内没有借阅记录的可借图书，这样找出长期没人借、占地方的书。
54. 作为管理员，我想从没被借过、上架满阈值的可借图书也算作旧书，这样冷门书也会被发现。
55. 作为管理员，我想在借的图书和最近被借过的图书都不在旧书清单里，这样不会误清热门书。
56. 作为管理员，我想确认一次就把清单里的旧书全部下架，这样不用一本本操作。
57. 作为管理员，我想在不确认时什么都不改变，这样能先看看清单再决定。
58. 作为管理员，我想没有旧书时看到明确提示，而不是空清单让我确认，这样不会做无意义的操作。
59. 作为维护者，我想旧书阈值默认 365 天，并可以在配置里调整，这样能适应不同的清理节奏。

### 数据与可靠性

60. 作为用户，我想每次修改操作完成后数据立即保存，这样关掉程序再打开时数据都在。
61. 作为用户，我想程序在保存中途崩溃时原有数据完好无损，这样不会因为一次意外丢掉全部馆藏。
62. 作为用户，我想保存失败（例如磁盘满）时看到"保存失败"，并且这次操作完全没有生效，这样屏幕上显示的和文件里存的始终一致。
63. 作为维护者，我想图书和借阅记录文件不存在时程序当作空数据正常启动，这样第一次运行不需要准备文件。
64. 作为维护者，我想数据文件的表头和程序预期不符时启动报错，这样手工编辑写错列时能马上发现，而不是读出错乱的数据。
65. 作为维护者，我想数据文件是人能直接阅读和编辑的文本，这样出问题时能手工检查和修复。

## Implementation Decisions

### 分层与装配

- 四层，依赖只能自上而下：界面层 → 业务层 → 仓储层 → 存储层，存储层再调用自写的 `file-utils.jar`。模型和配置被各层引用。
- 程序入口在启动时一次性创建所有对象，通过构造器注入，不用单例。
- 权限只在界面层控制：菜单按角色过滤，业务层不再重复校验角色。
- 仓储是具体类，不抽接口；以后真要换存储方式时再提取。

### 模块与接口

根包 `com.library` 下共 7 个包、20 个类。界面层不含业务规则，业务层不碰输入输出和文件，模型只是数据对象。

| 包 | 类 | 职责 |
| --- | --- | --- |
| app | `LibraryApp` | 程序入口；创建并组装所有对象；运行「登录 → 菜单」循环 |
| ui | `ConsoleIO` | 唯一的控制台输入输出入口：`readInt`、`readLine`、`readOptional`（回车表示保留原值）；非法输入提示后重问 |
| ui | `LoginView` | 登录界面：输入用户 ID，或选择退出程序 |
| ui | `MenuController` | 按角色列出菜单、读取选择、调用服务、显示结果；统一捕获 `BusinessException` 和 `UncheckedIOException` 并提示 |
| ui | `MenuOption` | 枚举：菜单编号、名称、可用角色 |
| service | `AuthService` | 按用户 ID 登录 |
| service | `BookService` | 查找、浏览、上架、修改、下架、旧书清理 |
| service | `BorrowService` | 借阅、归还、我的借阅、库存状态（借给了谁） |
| service | `StatsService` | 累计借阅次数统计、热门前 K |
| service | `BusinessException` | 违反业务规则；运行时异常，携带给用户看的原因 |
| repository | `BookRepository` | 图书的新增、更新、查询、`nextId()` |
| repository | `BorrowRecordRepository` | 借阅记录的新增、更新；按读者或按图书查询；按图书计数 |
| repository | `UserRepository` | 按 ID 查用户 |
| storage | `TsvTable` | `read(path, header)` 返回 `List<String[]>`，`write(path, header, rows)`；负责字段转义和表头校验，内部调用 `com.fileutil.FileUtil` |
| model | `Book` | id、title、author、category、publishYear、shelvedOn、status |
| model | `BookStatus` | 枚举：`ACTIVE`（在馆）、`REMOVED`（已下架） |
| model | `BorrowRecord` | id、userId、bookId、borrowedOn、returnedOn（未归还时为空） |
| model | `User`、`Role` | id、name、role；`Role` 枚举为 `ADMIN`、`READER` |
| config | `LibraryConfig` | 数据目录（默认 `data/`）、借阅上限 `maxBorrowPerReader`（默认 5）、旧书阈值（默认 365 天） |

- 需要日期的服务通过构造器接收 `java.time.Clock`，不直接调用 `LocalDate.now()`。
- 仓储在启动时把整个文件读入内存。

### 领域规则（见 `GLOSSARY.md` 和 ADR）

- 图书上不存"是否在借"和"累计借阅次数"，两者都从借阅记录推导（ADR 0001）。
- 下架是软删除，不可恢复；新 ID = 已有最大 ID + 1，永不复用（ADR 0002）。
- 已下架图书只出现在累计借阅次数统计和"我的借阅"历史里，其他所有视图和按 ID 的操作都把它当作不存在。
- 字段校验：书名、作者、类别去掉首尾空格后不能为空；出版年份为 1 到今年（按注入的 Clock 取）的整数。
- 热门前 K 只统计在馆图书，按次数降序、ID 升序；K 超出时返回全部。

### 持久化（ADR 0003）

- 三个 UTF-8 文本文件：用户、图书、借阅记录，放在配置的数据目录下，扩展名 `.tsv`。
- 行格式：字段之间用一个 Tab 分隔；字段里的 `\`、Tab、换行分别写成 `\\`、`\t`、`\n`，所以一条记录永远只占一行。首行是表头，读取时校验。
- 表头：
  - 用户：`id name role`
  - 图书：`id title author category publishYear shelvedOn status`
  - 借阅记录：`id userId bookId borrowedOn returnedOn`

  日期为 ISO 格式，未归还时归还日期为空字段。
- `file-utils.jar` 只提供两个操作：读出全部行（文件不存在时返回空列表）；整体原子替换写入（先写临时文件，再原子替换原文件，并自动创建父目录）。jar 已实现并放进项目依赖。
- 写顺序：仓储先把新的完整数据写入文件，成功后再更新内存。写失败时抛出非受检的 IO 异常，菜单控制器提示"保存失败"，内存不变。
- 缺文件：图书、借阅记录文件不存在时视为空，第一次保存时创建；用户文件不存在或没有数据行时启动报错。
- 仓库提交一份示例用户文件（1 个管理员、1 个读者）；运行时产生的图书和借阅记录文件，以及临时文件，都不提交。

- JDK 17，IntelliJ IDEA 模块，不用 Maven。
- 根包名 `com.library`。

## Testing Decisions

- **测试由开发者自己写**，用 JUnit 5，不走 TDD。本节只确定测试边界，不规定写测试的顺序。
- **好的测试只检查外部行为**：调用公开方法，断言返回值、抛出的业务异常，以及"重启"之后读到的数据。不断言私有字段、内部集合，不检查文件的具体字节。
- **唯一的测试缝：业务层服务的公开方法。**
  - 每个测试用一个临时目录做数据目录，真实创建仓储、存储层和 jar，不用假对象。
  - 用固定的 Clock 控制"今天"，以覆盖上架满阈值、出版年份上限、借阅和归还日期等场景。
  - "重启"场景：操作完成后，用同一个数据目录重新创建仓储和服务，再查询结果。持久化、转义（书名含 Tab、换行、反斜杠、逗号）和 ID 不复用都通过这条路径验证，存储层不单独测试。
  - 启动报错（用户文件缺失或为空、表头不符）通过"在临时目录准备好文件，然后创建仓储"来测试。
- **被测模块**：登录服务、图书服务、借阅服务、统计服务；存储层和仓储通过服务间接覆盖。
- **不写自动测试**：界面层（输入重问、菜单过滤、提示文字）在每张票据完成时手动在控制台演示验收。
- **可参照的已有测试**：仓库里还没有。第一张票据的服务测试就是后续测试的样板。

## Out of Scope

- 密码、权限体系以外的任何安全措施。
- 在程序里增删用户、修改用户角色。
- 恢复已下架的图书、物理删除图书或借阅记录。
- 预约、续借、逾期和罚款。
- 同一种书的多本副本（每本图书都是独立的一条记录）。
- 多进程或多台电脑同时访问同一份数据。
- 数据库、网络服务、图形界面。
- 迁移旧格式的数据文件（之前没有任何数据）。
- 界面层的自动测试。
